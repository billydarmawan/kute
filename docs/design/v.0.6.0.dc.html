0.6.0

Argo CD support — one tier shallower than Flux, on purpose

Flux earned a bespoke join view (30b) because it has no UI. Argo has a good dashboard — so kute doesn't rebuild it. 0.6.0 is the 30a/32a treatment only: a curated registry entry for Application, the same timeline enrichment, and honest kubectl verbs. The line kute owns is the 2am terminal moment — see the Degraded app, jump to its broken workload, read the exit code, no browser, no SSO.

  • Sync and health are independent axes, so they get independent columns — Synced+Degraded (billing: git is right, workload is sick) and OutOfSync+Healthy (frontend: drift, nothing broken) are different incidents. Sort order: Degraded → OutOfSync → Progressing → Healthy.
  • The sub-line does the diagnosis — Argo's own status already names the sickest resource; kute prints it verbatim and ↵ routes straight to that Deployment (principle 4), skipping the app-detail hop entirely.
  • Sync is `reversible`-class with the will-run line — patching `.operation` is exactly what the argocd CLI does; kute just shows it. `prune=true` sync would be `delete`-class (y/N in keybar).
  • `u` is the concession to the dashboard — for sync waves, app-of-apps graphs, and diffs, the right tool exists; kute hands you the deep link (URL from argocd-cm) instead of imitating it. No 30b-style tree for Argo, by design.
  • drift delta `−3` reuses the 30b convention; commit-subject enrichment follows the same 4-tier ladder as Flux (event parse → per-context cache → local git by SHA → SHA only).
